## Create the Package and Generate the Service

Create package `ZRAP120_AI_{{ $doc.input.groupId }}` under `ZLOCAL`, with description `RAP AI Package {{ $doc.input.groupId }}`, and add it to favorite packages. This package contains the generated and adjusted artifacts.

The course follows these primary artifacts as the generated project evolves:

- `ZRAP120_AI_{{ $doc.input.groupId }}/behavior/ZR_TRAVEL{{ $doc.input.groupId }}.bdef`
- `ZRAP120_AI_{{ $doc.input.groupId }}/behavior/ZBP_R_TRAVEL{{ $doc.input.groupId }}.locals_imp.abap`
- `ZRAP120_AI_{{ $doc.input.groupId }}/classes/ZCL_TRAVEL_HELPER_{{ $doc.input.groupId }}.clas.abap`
- `ZRAP120_AI_{{ $doc.input.groupId }}/cds/ZR_BOOKING{{ $doc.input.groupId }}.asddls`
- `ZRAP120_AI_{{ $doc.input.groupId }}/metadata/ZC_TRAVEL{{ $doc.input.groupId }}.asddlx`
- `ZRAP120_AI_{{ $doc.input.groupId }}/metadata/ZC_BOOKING{{ $doc.input.groupId }}.asddlx`

::course-checkpoint{id="package-created" title="Package ready"}
The package exists under `ZLOCAL` and is available in your favorite packages.
::

Right-click package `ZRAP120_AI_{{ $doc.input.groupId }}`, select **Generate ABAP Repository Objects**, choose **OData UI Service from Scratch**, and keep the package name. Paste the first prompt:

::code-tree-intersection

```text [prompts/1.generate-travel-service.md]
Create a transactional application for travel management with DRAFT.
Create the entity Travel based on the structure /DMO/TRAVEL_DATA.
The second entity is Booking based on /DMO/BOOKING_DATA.
The generated objects should end with suffix "{{ $doc.input.groupId }}".
```

::

Accept the generated `Travel` and `Booking` entities, then add the workshop-specific fields:

::code-tree-intersection

```text [prompts/2.add-travel-fields.md]
Add Destination field for entity Travel, use /DMO/CITY as data element.
Add SightseeingsTips field for entity Travel, use /DMO/DESCRIPTION as data element.
Add DiscountedFlightPrice field for entity Booking, use /DMO/FLIGHT_PRICE as data element.
```

::

Before you generate the RAP business object, review the generated service configuration:

- `Travel` has `Destination` and `SightseeingsTips`.
- `Booking` has `DiscountedFlightPrice`.
- `BookingFee` and `TotalPrice` use `CurrencyCode`.
- `BookingFeeCurr` is removed.
- `DiscountedFlightPrice` and `FlightPrice` use `CurrencyCode`.
- `FlighPriceCurr` is removed.

Click **Next**, review the generated object preview, select a transport request, click **Finish**, and refresh the package with **F5** if needed.

::course-checkpoint{id="service-generated" title="Service generated"}
The generated `Travel` and `Booking` artifacts are visible in the package and activate without errors.
::

::note
Generated artifact names, database fields, and other elements may differ because they are generated by GenAI. Use the generated artifacts as your local baseline and apply the following code to the matching objects.
::

## Add the Helper Class

Create class `ZCL_TRAVEL_HELPER_{{ $doc.input.groupId }}` with description `Travel helper class {{ $doc.input.groupId }}`. This helper centralizes business logic that later validations and determinations reuse.

::code-tree-intersection

```abap [ZRAP120_AI_{{ $doc.input.groupId }}/classes/ZCL_TRAVEL_HELPER_{{ $doc.input.groupId }}.clas.abap] {6-15,23-42}
CLASS zcl_travel_helper_{{ $doc.input.groupId }} DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC.

  PUBLIC SECTION.
    METHODS validate_customer
      IMPORTING iv_customer_id TYPE /dmo/customer_id
      RETURNING VALUE(rv_exists) TYPE abap_bool.
    METHODS get_booking_status
      IMPORTING iv_status TYPE /dmo/booking_status_text
      RETURNING VALUE(rv_status) TYPE /dmo/booking_status.
    METHODS get_sightseeing_tips
      IMPORTING iv_city TYPE /dmo/city
      RETURNING VALUE(rv_sightseeing_tips) TYPE /dmo/description.

  PROTECTED SECTION.
  PRIVATE SECTION.
ENDCLASS.

CLASS zcl_travel_helper_{{ $doc.input.groupId }} IMPLEMENTATION.
  METHOD validate_customer.
    SELECT SINGLE
      FROM /dmo/customer
      FIELDS @abap_true AS line_exists
      WHERE customer_id = @iv_customer_id
      INTO @rv_exists.
  ENDMETHOD.

  METHOD get_booking_status.
    CASE iv_status.
      WHEN 'Booked'.
        rv_status = 'B'.
      WHEN 'New'.
        rv_status = 'N'.
      WHEN 'Cancelled'.
        rv_status = 'X'.
    ENDCASE.
  ENDMETHOD.

  METHOD get_sightseeing_tips.
    " We will use the ABAP AI SDK powered by ISLM to call an LLM and generate sightseeing tips for a specific city.
  ENDMETHOD.
ENDCLASS.
```
